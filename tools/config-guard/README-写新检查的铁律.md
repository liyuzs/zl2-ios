# 写新检查的铁律

> 这是从 ios-zl2 里**一条条踩出来的**，不是设计出来的。**条数会继续长** —— 所以标题里不写数字（第180轮那条规矩，我刚又犯了一次）。
> 每条后面写着"踩过几次、在哪轮"——因为**只有踩过的人才记得住**。
>
> 写新检查前读一遍，写完后逐条对一遍；**改判据之后，第 9 条要再看一次**。

---

## 1. 用 `_paths`，别写死路径

```js
// ❌ 换台机器就跑不了，而且你一定会忘（我已经忘了 3 次）
const SRC = 'D:\\ios-zl2\\src';

// ✓
const { SRC } = require('./_paths');
```

**踩过 3 次**（183/184/185 → 187 轮才被 `_check-script-inventory` 拦住）。
**别指望"下次会记得"** —— 直接跑 `_check-script-inventory`，它会告诉你。

---

## 2. 扫描前剥注释

注释里提到代码片段（`` `out.write(to:)` ``、`` `case .c:` ``）**会骗过正则**。

**踩过 3 次**（143 / 150 / 175 轮）。默认动作：`line.trim().startsWith('//')` 直接跳过。

---

## 3. 剥"定义行"，不只是注释

**同一个词在"定义"和"使用"里长得一模一样**：
· `case .c:`（消费）vs `throw .c`（创建）→ 175 轮
· `@State var x = 42`（初值）vs `x = 42`（赋值）→ 177 轮

**后果是判据彻底空转**（每个都"看起来被用过"），而输出仍然显示"✓ 通过"。
**修法**：判"使用"时先过滤掉定义行。

---

## 4. 分母要和"独立粗数"对账

**"0 处问题"和"5 处问题"一样可疑 —— 除非你能证明项目里真的只有那么多。**

185 轮：判据报"5 处 case"，而全项目实际有 **336 处** —— **分母差两个数量级 = 判据根本没匹配上**。

**做法**：写完后用**一条最粗暴的正则**（`grep -c '^\s*case\s+\.'`）数一遍，看是否同量级。

**注意**：**粗数本身也要校准**（186 轮：第一版粗数把 `extension` 和 `@MainActor` 算进去了）。
**粗数要故意写得笨** —— 少算比多算安全（少算会引人去查，多算会冤枉判据）。

---

## 5. 三向注入验证

改完判据后**必须**做：
| 方向 | 期望 |
|---|---|
| 造一个**真问题** | **必须报** |
| 造一个**看起来像但不是** | **必须不报** |
| 造一个**局限里说抓不到的** | **应该不报**（报了说明局限写错了）|

**第 167 轮起，这条已经抓到 6 次判据失效** —— 包括"pattern 把 `case .c:` 当创建"（175）、
"豁免范围 6 行导致相邻 case 互相覆盖"（175）、"篡改后判据仍通过"（172）。

---

## 6. 先数分母，再决定做不做

| 分母 | 结论 |
|---|---|
| **0** | **不做** —— 空转，永远绿 |
| 1–10 | 先问"会不会增长"；不增长就不做 |
| 10–100 | 有真问题就做 |
| 100+ | **做** —— 哪怕现在全对，也守得住未来 |

**两次因为这个判断而放弃**：
· 184 轮 `case .typo` 拼错（误报 16%，全是系统枚举）
· 188 轮 魔法数字重复（453 组误报 / 真问题 1，根因"文本相同 ≠ 语义相同"）

**"做不到"和"还没做"是两件事** —— 判据需要的信息不在文本里（如"是不是耦合"），就是做不到。
**放弃理由要写进相邻检查的局限段**，否则将来会重新试一遍。

## 7. 写清局限（`_check-check-metadata` 会强制）

头部必须有 `**局限**` 或 `局限：`，说清：
· 只认哪些写法
· 什么情况会误报
· **哪些是"做不到"而不是"还没做"**

**这不是形式主义** —— 第 135 轮起，正是它让人发现"这条检查其实一直在空转"。

## 8. 做完跑全套，别靠记性

```powershell
& 'C:\Users\21793\.dsh\config-guard\_run-all.ps1'
node 'C:\Users\21793\.dsh\config-guard\_check-script-inventory.js'
& 'C:\Users\21793\.dsh\config-guard\_spot-check.ps1'
```

`_check-script-inventory` 会抓：**没登记清单** / **清单里有但磁盘没有** / **写死了路径**。
`_check-check-metadata` 会抓：**没写局限**。

**187 轮那条的结论**：**记性会忘，检查不会。**
不要立"下次注意"的 flag —— **去找到那个会拦住你的检查；没有就写一个。**

## 9. 改判据之后，三向注入要**重跑**

**上面第 5 条说的是"写完之后验证"。这条说的是"改完之后重新验证"——
因为改判据就是一次可能引入空转的手术。**

关键是不对称：

| 调整方向 | 风险 | 会不会被发现 |
|---|---|---|
| **收紧**（多报） | 假警报 → 让人改坏本来正确的代码 | **会**（有人抱怨）|
| **放宽**（少报） | **空转** → 该抓的抓不到，而检查显示 ✓ | **不会** |

**"放宽过度"是无声的** —— 它让检查永远绿，而没人会去看一个永远绿的检查。

**所以每次改判据（收或放），三向注入全跑一遍；特别是"放宽"之后，
"该抓的那一向"一定重跑** —— 因为"放宽过头"的证据只会出现在那里。

**194 轮实例**：`_check-startup-io` 判「调 `directorySize(` 时有没有 `includeSize` 门控」，
原来只判**同一行**（当前三元写法正好同行 ✓，但改写成 `if includeSize { ... }` 就会假警报）。
改成**看窗口**（前 2 行 + 本行 + 后 1 行）后，双向注入证明：
· 改写成 `if` 门控 → **不报**（不再冤枉）
· 真的去掉门控 → **仍然会报**（没放宽过头）

## 10. 定期做"覆盖地图"，找没人管的地方

**不是问"这个检查准不准"（深挖），而是问"这张网有没有漏掉的区域"（横扫）。**

两者发现的东西不一样：
· **深挖** → 发现问题在**已有检查的内部**（判据失效、分母不对、假警报）
· **横扫** → 才发现"**那里根本没有检查**"

**做法**：把每项检查管什么列出来，然后问：
> **"项目里还有哪些事情在发生，而这张表里没有对应的一行？"**

**答案通常落在"副作用"上** —— 日志、缓存、临时文件、定时器、后台任务、重试、通知订阅。
因为**功能会被检查，副作用容易被漏**：写功能时会想"这个功能对不对"，
而写日志/写临时文件时，那是"顺便记一笔"，不会想到"这笔会不会有问题"。

**已查过的副作用（ios-zl2）**：
| 副作用 | 状态 |
|---|---|
| **日志**（NSLog/print）| **198 轮补了 `_check-log-secrets`**（之前整张检查网里没人管它）|
| 缓存文件 | ✓ 有清理（`ZLUpdate` 清过期日志）|
| 临时文件 | ✓ 199 轮核实：`DiagnosticsScreen` / `VersionManageScreens` / `VersionIconPicker` 用完都删 |
| 定时器 | ✓ `LanDiscovery` / `GameOverlay` 都有 `invalidate`；`Timer.publish` 随 View 生命周期 |
| 通知 / Combine 订阅 | ✓ 0 处（项目不用手工通知）|
| 网络请求 | ✓ 18 个全部设了超时（193 轮）|

## 附：一条元原则

**检查全绿只能证明"我想到的都对了"，不能证明"能跑起来"。**
（183 轮才发现一个 `invalid redeclaration` —— 因为编译器从来没跑过。）

所以每次加检查，也问一句：**"它验证的这件事，是不是已经有更可靠的机制在管？"**
如果在管 → 别加；如果没人管且你加不了 → **写进 STATUS 的已知限制**。

## 第 11 条：改完文件，看 `git diff --stat` 的规模对不对

**一条自检，成本两秒，能抓住一整类事故。**

**判据**：改完之后跑 `git diff --stat`。**如果改动行数远超你实际改的量，就是"横切属性"被洗了**（换行符 / 编码 / BOM / 行尾空格）。

ios-zl2 的这个坑踩过两次，**原因不同但表现一样**：

| 轮次 | 怎么发生的 | 表现 |
|---|---|---|
| 175 | 我**推测**"同类文件都是 LF"，把一个原本 CRLF 的文件转成了 LF | `AccountService.swift` 显示 554/545 变更，`git diff -w` 只有 13/4 |
| **223** | 插入脚本用 `lines.split(/\r?\n/).join('\n')` —— **天然丢 CRLF** | `_check-dead-routes.js` 显示 276 行变更，`diff -w` **为空** |

### 固定的两步自检

```powershell
git diff --stat              # 规模对不对？我只加了 8 行，为什么显示 252？
git diff -w --stat           # 忽略空白后还剩什么？为空 = 纯粹是格式噪音
```

**`-w` 后变小 → 格式问题；`-w` 后不变 → 真改动了内容。**

### 写"读全文 → 改 → 写回"的脚本时，显式保留换行符

```js
const raw = fs.readFileSync(p, 'utf8');
const eol = raw.includes('\r\n') ? '\r\n' : '\n';   // ← 先问它现在是什么
const lines = raw.split(/\r?\n/);
// …改 lines…
fs.writeFileSync(p, lines.join(eol));
```

**不要用 `join('\n')` 一把梭** —— 它在 LF 文件上无害，在 CRLF 文件上把整个文件重写一遍。

一句话：**这个仓库是混合换行的，所以"文件本来的换行符"必须当成输入读进来，不能当成默认值。**
