# 版本隔离实现说明

> ⚠️ **这个功能当前不可用（已置灰）** —— 第29轮实测：核心 `JavaLauncher.m:179-182` 在元数据启动分支里**自己拼游戏目录、完全忽略 `GAME_DIR`**，所以靠 setenv 改不到真实目录。UI 显示模组在 `versions/<id>/mods`，游戏实际读 `<mcRoot>/mods` —— 会误导用户。设置项已进 `ZLUnsupportedSettings.notWired` 并写明原因。
>
> 保留本文是因为它记录了**怎么做的、为什么不行**，将来若要重做需先解决"核心忽略 GAME_DIR"这个前提。


> 日期：2026-11-08
> 状态：**已实现，待真机验证**

---

## 一、两种「隔离」别搞混

| 概念 | 层级 | 现状 |
|---|---|---|
| **实例隔离** | `<Documents>/instances/<实例名>/.minecraft` | 早就有了（`GameDirectoryStore`，188 行） |
| **版本隔离** | 同一实例内，每个游戏版本自己的目录 | **本次实现** |

实例隔离解决的是「和朋友分开玩不同的整合包」；
版本隔离解决的是「同一个整合包里 1.20.1 和 1.21.4 的模组别打架」。

---

## 二、问题是什么

原来的目录结构：

```
.minecraft/
├── versions/
│   ├── 1.20.1-fabric/      ← 只有版本元数据和 jar
│   └── 1.21.4-fabric/
├── mods/                   ← ⚠️ 所有版本共享
├── saves/                  ← ⚠️ 所有版本共享
├── resourcepacks/          ← ⚠️ 所有版本共享
└── config/                 ← ⚠️ 所有版本共享
```

装了两个版本后：

- 1.20.1 能用的模组，1.21.4 加载时直接崩
- 存档混在一起，进错版本就报「世界版本不兼容」
- 配置文件互相覆盖

这是真实会踩的坑，不是理论问题。

---

## 三、实现方案

开启「全局版本隔离」（默认开）后：

```
.minecraft/
├── versions/
│   ├── 1.20.1-fabric/
│   │   ├── 1.20.1-fabric.json
│   │   ├── 1.20.1-fabric.jar
│   │   ├── mods/           ← ✅ 独立
│   │   ├── saves/          ← ✅ 独立
│   │   ├── resourcepacks/  ← ✅ 独立
│   │   ├── shaderpacks/    ← ✅ 独立
│   │   ├── config/         ← ✅ 独立
│   │   ├── logs/
│   │   ├── crash-reports/
│   │   ├── screenshots/
│   │   └── options.txt     ← ✅ 首次从全局复制一份
│   └── 1.21.4-fabric/
│       └── ...（同上）
├── libraries/              ← 共享（避免每个版本重下几百 MB）
└── assets/                 ← 共享
```

**关键取舍**：`libraries` 和 `assets` **不隔离**。
理由：它们由 Mojang 校验哈希，跨版本可复用，隔离会让每个版本多占几百 MB。安卓 ZL2 也是这么做的。

## 四、代码链路

```
设置项 versionIsolation (ZLSettings.swift:56, 默认 true)
        ↓
VersionRepository.isolationEnabled          (第 51 行)
        ↓
VersionRepository.gameDir(for: versionID)   (第 65 行)  ← 核心判断
        ↓
   ┌────┴────┬─────────┬──────────┐
   ↓         ↓         ↓          ↓
prepareIsolatedDir  modsDir  savesDir  各管理页
(CoreBridge 启动时)  (模组页)  (存档页)
```

### 各接入点

| 位置 | 行号 | 作用 |
|---|---|---|
| `VersionRepository.gameDir(for:)` | 65 | 隔离开 → `versions/<id>/`，否则 `mcRoot` |
| `VersionRepository.prepareIsolatedDir(for:)` | 73 | 建目录 + 8 个子目录 + 复制 options.txt |
| `CoreBridge.launchVersion` | 187 | 启动前 `setenv("GAME_DIR", 隔离目录)` |
| `CoreBridge.launchJar` | 242 | 直接跑 jar 时用 jar 名建隔离目录 |
| `ModsManagerScreen.modsDir` | 52 | 模组列表读写 |
| `SavesManagerScreen.savesDir` | 163 | 存档列表读写 |
| `ResourceManagerScreen.folderURL` | 57 | 资源包/光影 |
| `ZL2FabricAPIInstaller.install` | 368 | 下载 Fabric API 到对应版本 |

## 五、UI 上的变化

设置页 → 游戏设置 → **全局版本隔离** 下方新增一行实时状态：

```
当前隔离规则    每个版本独立目录：versions/<版本>/ 下的 mods · saves · config
```

关掉开关后变成：

```
当前隔离规则    所有版本共用：.minecraft/ 下的 mods · saves · config
```

这样用户一眼就知道自己的模组现在放在哪。

## 六、注意事项

### 1. 切开关不会搬迁已有数据

从「共享」切到「隔离」，原来的 `mods/` 不会自动搬进各版本目录。

**这是有意的**：
- 自动搬容易搬错（不知道该搬给哪个版本）
- 用户可能需要把同一个模组放到多个版本

如果需要，可以在模组管理页手动「从全局导入」。

### 2. 首次启动会多几个空目录

`prepareIsolatedDir` 会建 8 个子目录。都是空壳，几十字节，不影响。

### 3. options.txt 只复制一次

版本目录里已经有 `options.txt` 就不再覆盖，避免用户调的画面设置被冲掉。

### 4. 直接跑 jar 时的伪版本 ID

`launchJar` 没有版本 ID，用 jar 文件名当目录名。好处是测试产生的存档不会混进主目录。

## 七、真机验证要点

1. **开两个版本，各装一个不同的模组**
   - 进 1.20.1 → 只看到模组 A
   - 进 1.21.4 → 只看到模组 B
   - 如果都能看到对方的，说明 `GAME_DIR` 没生效

2. **看日志里的这行**

   ```
   [ZL2] GAME_DIR = /path/instances/default/.minecraft/versions/1.20.1-fabric (隔离=开)
   ```

   路径里必须带 `versions/<版本ID>`。

3. **关掉隔离再试**
   - 两个版本都回落到 `.minecraft/mods`
   - 这时候所有模组都会出现

4. **检查文件树**

   ```
   Documents/instances/default/.minecraft/versions/1.20.1-fabric/mods/
   ```

   应该有独立目录。
