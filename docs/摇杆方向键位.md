# 摇杆方向键位对接

> 日期：2026-11-08 第 19 轮
> 补上控制布局最后一块：摇杆的八方向键位

---

## 一、问题在哪

ZL2 的摇杆支持自定义八方向键位（`directionEvents`）：

```swift
static let directionEvents: [String: [ZLClickEvent]] = [
    "north":      [.key("GLFW_KEY_W")],
    "north_east": [.key("GLFW_KEY_W"), .key("GLFW_KEY_D")],
    "north_west": [.key("GLFW_KEY_W"), .key("GLFW_KEY_A")],
    "south":      [.key("GLFW_KEY_S")],
    "south_east": [.key("GLFW_KEY_S"), .key("GLFW_KEY_D")],
    "south_west": [.key("GLFW_KEY_S"), .key("GLFW_KEY_A")],
    "east":       [.key("GLFW_KEY_D")],
    "west":       [.key("GLFW_KEY_A")],
]
```

**但核心的 `ControlJoystick.m` 把这四个键写死了：**

```objc
CallbackBridge_nativeSendKey(GLFW_KEY_W, 0, direction >= NE && direction <= NW, mod);
CallbackBridge_nativeSendKey(GLFW_KEY_A, 0, direction >= NW && direction <= SW, mod);
CallbackBridge_nativeSendKey(GLFW_KEY_S, 0, direction >= SW && direction <= SE, mod);
CallbackBridge_nativeSendKey(GLFW_KEY_D, 0, direction == SE || direction == E || direction == NE, mod);
```

**完全忽略布局文件里配的键位。**

所以用户在编辑器里把摇杆改成「北=上箭头」，进游戏还是 WASD。

---

## 二、核心的方向编号

`ControlJoystick.m` 顶部定义：

```objc
#define DIRECTION_EAST 0
#define DIRECTION_NORTH_EAST 1
#define DIRECTION_NORTH 2
#define DIRECTION_NORTH_WEST 3
//#define DIRECTION_WEST 4       ← 注释掉了
#define DIRECTION_SOUTH_WEST 5
//#define DIRECTION_SOUTH 6      ← 注释掉了
#define DIRECTION_SOUTH_EAST 7
```

WEST 和 SOUTH 虽然被注释，但计算逻辑 `(degree+22.5)/45.0 % 8` 会产生 0-7 全部值，所以实际运行时会用到。

**8 个方向都要填。**

---

## 三、实现

### 3.1 核心侧改动

`core/customcontrols/ControlJoystick.m`：

```objc
// 从布局读 32 个整数（8 方向 × 4 键位）
NSArray *dirKeys = self.properties[@"directionKeycodes"];

if (dirKeys != nil && dirKeys.count >= 32) {
    // 新路径：按配置发送
    NSMutableSet *shouldBeDown = [NSMutableSet set];
    if (direction >= 0) {
        int base = direction * 4;
        for (int slot = 0; slot < 4; slot++) {
            int kc = [dirKeys[base + slot] intValue];
            if (kc > 0) [shouldBeDown addObject:@(kc)];
        }
    }
    // 松开不再需要的
    for (NSNumber *n in self.activeDirectionKeys) {
        if (![shouldBeDown containsObject:n]) {
            CallbackBridge_nativeSendKey([n intValue], 0, 0, mod);
        }
    }
    // 按下新需要的
    for (NSNumber *n in shouldBeDown) {
        if (![self.activeDirectionKeys containsObject:n]) {
            CallbackBridge_nativeSendKey([n intValue], 0, 1, mod);
        }
    }
    self.activeDirectionKeys = shouldBeDown;
} else {
    // 旧路径：保持原来的写死 WASD（旧布局兼容）
    ...
}
```

**关键设计**：用 `activeDirectionKeys` 集合做差分，算出「该松开哪些、该按下哪些」。

不能每帧全发一遍——那样会频繁触发按下/抬起事件，游戏里表现成角色一顿一顿的。

### 3.2 导出侧改动

`CoreLayoutExporter.directionKeycodes(for:)`：

```swift
static func directionKeycodes(for joy: ZLJoystick) -> [Int] {
    let order: [ZLJoystickDirection] = [
        .east, .northEast, .north, .northWest,
        .west, .southWest, .south, .southEast,
    ]

    var out = [Int](repeating: 0, count: 32)
    let events = joy.directionEvents.isEmpty ? ZLJoystickDefaults.directionEvents
                                             : joy.directionEvents

    for (idx, dir) in order.enumerated() {
        guard let list = events[dir.rawValue] else { continue }
        var slot = 0
        for ev in list where ev.type == .key {
            guard slot < 4 else { break }
            if let code = GLFWKeyNames.code(for: ev.value), code > 0 {
                out[idx * 4 + slot] = code
                slot += 1
            }
        }
    }
    return out
}
```

产出 `directionKeycodes: [32 个整数]`，塞进摇杆的 properties。

## 六、兼容性

**旧布局不受影响**：如果 `directionKeycodes` 字段不存在（字段数 < 32），走原来的写死 WASD 路径。

**新导出的布局**才有自定义方向键位。

---

## 七、真机验证要点

1. **默认行为不变**
   - 不做任何配置，摇杆应该是 WASD 八向
   - 这和之前应该完全一样

2. **自定义方向键**
   - 编辑器里把「北」改成上箭头（`GLFW_KEY_UP`）
   - 进游戏推摇杆向上，角色应该往上走（MC 里默认没绑上箭头，所以应该没反应）
   - 换成把「北」绑到 `GLFW_KEY_SPACE`，推上应该跳

3. **切换方向不抖动**
   - 摇杆从北推到东北，应该保持 W 按下，额外按下 D
   - 不应该出现 W 抬起再按下的中间态
