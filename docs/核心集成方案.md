## 0. TL;DR（先看这 5 条）

1. **Amethyst 没有可复用的库/framework target。** `Amethyst.xcodeproj/project.pbxproj` 全文只有 **一个** target，而且是 `PBXLegacyTarget`——它只是调用 `gmake` 跑根目录 `Makefile`，真正的产物是**一个完整的 `.app`（`AngelAuraAmethyst`，`add_executable`，见 `Natives/CMakeLists.txt:96`）**。所以官方意义上「加个子工程 / 出个 xcframework」这条路**不存在现成答案**，要自己改造 CMake。
2. **真正可调的入口只有一个 C 函数**（`Natives/JavaLauncher.h:20`）：
   `int launchJVM(NSString *username, id launchTarget, int width, int height, int minVersion);`
   它内部 `dlopen` 目标 JRE 的 `libjli.dylib`、拼 100+ 个 JVM 参数，最后调 `JLI_Launch(...)`。
3. **一行代码就能跑的最小验证路径**：`launchJVM(nil, @"<某个 .jar 路径>", w, h, 8)` —— `launchTarget` 传 `NSString` 走「跑 jar」分支（`Natives/JavaLauncher.m:181-185`、`Natives/JavaGUIViewController.m:317`）。这条路**不需要**版本 JSON、不需要资源下载器，最适合当第一个里程碑。
4. **体积主要由四块构成**（实测字节数见 §4）：`Frameworks/` 下 14 个 dylib ≈ **47.4 MB**；`libs/` 下 LWJGL/cacio jar ≈ **9.6 MB**；**四套 JRE 的 zip ≈ 93.4 MB**（解压后更大，未确认）；第三方 App 级 framework（AltKit/UnzipKit 等）。整体是 **150 MB 量级起步**的工程。
5. **拦路虎不是代码而是签名/权限**：JIT（`get-task-allow` / TrollStore / StikDebug）、`com.apple.private.memorystatus`（自设 Jetsam 上限）、`com.apple.developer.kernel.increased-memory-limit`、`com.apple.private.security.no-sandbox`（TrollStore 版）。普通免费开发者账号能编能装，但**大概率启动即崩或极卡**（见 §6）。

### 2.3 它自己的 .xcodeproj 是「假」工程（已确认，`Amethyst.xcodeproj/project.pbxproj` 全文 162 行）

- ✅ 它可以被 Xcode 「打开」，但只是把 `make` 当构建脚本用；
- ❌ **不能** `drag into 我们的工程` 当子工程用（不产出 .a/.framework）；
- ❌ 官方**没有**发布任何 xcframework / 静态库。
- 另外：GitHub Releases 当前是**空数组**（`GET /repos/AngelAuraMC/Amethyst-iOS/releases?per_page=1` 返回 `[]`），也就是说连「下载官方 IPA 拆包复用」都没有正式版可下，只有 Actions 的 nightly 产物（README:58-61）。**是否存在可用的预编译 xcframework：未确认（极可能不存在）。**

### 2.4 三条可行路线对比（结论）

| 路线 | 做法 | 可行性 | 代价 |
|---|---|---|---|
| **A. 源码裁剪式集成（推荐）** | 把 `Natives/` 的源文件加进我们的 target，但**剔除** UI/账户/安装器/自定义控制，只留 JavaLauncher + 桥接 + SurfaceViewController | 高（改动可控） | 需要把 `add_executable` 改成 `add_library(... STATIC)` 自建一个 `libAmethystCore.a`，或直接把 .m 加进 XcodeGen sources |
| B. 子工程引入 | 把 `Amethyst.xcodeproj` 拖进来当依赖 | **不可行** | 它是 PBXLegacyTarget，不产出库 |
| C. 出 xcframework | 自己把 Natives 编成 `xcframework` 再分发 | 理论可行，需自己写脚本 | 收益低于 A（我们只有一个 App，没有多目标复用需求） |

> 建议走 **A**：新增一个 `AmethystCore` 静态库 target（或用 XcodeGen 的 `sources` 直接并入主 target），暴露一个 **ObjC 门面**（`AmethystLauncher.h/.m`）给 Swift 调；UI 完全由我们的 SwiftUI 负责。理由：`launchJVM` 本身对 UI 的依赖只有 3 处（见 §3.4），而 Amethyst 的 `main.m`/`AppDelegate`/`SceneDelegate`/`UIKit+hook` 会抢 `UIApplicationMain`，**必须排除**。

## 6. 问题 5：已知的坑（都有源码出处）

### 6.1 JIT —— 不是「优化项」，是「能否玩」的分水岭

Amethyst 判定 JIT 的方式（`Natives/utils.m:26-42`，逐字）：

```objc
BOOL isJITEnabled(BOOL checkCSFlags) {
    if (!checkCSFlags && (getEntitlementValue(@"dynamic-codesigning") || isJailbroken)) {
        return YES;
    }
    int flags;
    csops(getpid(), 0, &flags, sizeof(flags));
    if ((flags & CS_DEBUGGED) == 0) {
        return NO;
    }
    if (!DeviceHasJITFlags(JIT_FLAG_FORCE_MIRRORED | JIT_FLAG_HAS_TXM)) {
        return YES;
    }
    // Device with iOS 26+ and TXM requires a debugger attached for JIT script to bypass TXM restrictions
    return JIT26IsLikelyDebuggerKeepAttached();
}
```
即：**要么 `dynamic-codesigning` entitle（越狱）/ 越狱环境，要么进程带 `CS_DEBUGGED`（被调试）**。iOS 26 + TXM 设备还要求「调试器保持附着」并跑 JIT 脚本。

启动前的 JIT 门闸（`LauncherNavigationController.m:425-452`，逐字）：

```objc
- (void)invokeAfterJITEnabled:(void(^)(void))handler {
    BOOL hasTrollStoreJIT = getEntitlementValue(@"jb.pmap_cs.custom_trust");
    BOOL isLiveContainer = getenv("LC_HOME_PATH") != NULL;
    if (isJITEnabled(false)) { ...; handler(); return; }
    else if (hasTrollStoreJIT) {
        NSURL *jitURL = [NSURL URLWithString:[NSString stringWithFormat:@"apple-magnifier://enable-jit?bundle-id=%@", ...]];
        ...
    } else if (@available(iOS 17.4, *)) {
        ... "stikjit://enable-jit?bundle-id=%@&pid=%d%@"
    } else {
        ... "sidestore://sidejit-enable?pid=%d"
    }
    ...
    while (!isJITEnabled(false)) { /* 每 200ms 轮询 */ }
```
**通报**：iOS 17.4+ 走 StikDebug（`stikjit://`），16.7–17.3 走 SideStore（`sidestore://`），TrollStore 走 `apple-magnifier://`。这条逻辑**我们也要抄一份**，否则用户点了启动会卡在 `JLI_Launch` 里闪退。

TrollStore 自开 JIT 的部分（`main.m:315-335`）：
```objc
    if (!isJITEnabled(true) && getEntitlementValue(@"com.apple.private.security.no-sandbox")) {
        int ret = posix_spawnp(&pid, argv[0], NULL, NULL, (char*[]){argv[0], "", NULL}, environ);
        ... ptrace(PT_DETACH, pid, NULL, 0);
    }
```
—— 这依赖 `no-sandbox`，**免费证书拿不到**。

### 6.2 签名 / 沙盒

- 仓库自己的构建**强制 `ldid` 重签**（`Makefile:359-366`），并且对每个 Mach-O **逐个** `codesign`（`Makefile:422-427` + `METHOD_MACHO`）。我们的工程用 Apple 工具链签，规则不同：**外挂的 JRE 里所有 Mach-O 必须同样被签名**，否则 `dyld` 直接拒绝——这就是为什么 Amethyst 要在 `launchJVM` 里绕 `Library Validation`。
- `entitlements.codesign.xml` 里的 `com.apple.security.cs.disable-library-validation` 是 CoreTrust 层面允许加载**非同一 team 签名**的 dylib；没有它，`dlopen(libjli.dylib)` 会失败。
- README:45 原文：`Signing services that do not use your UDID ... are not supported, as Amethyst requires capabilities they do not allow`。
- 沙盒：`trollstore.xml` 里 `com.apple.private.security.no-sandbox` 一旦关掉，**必须同时声明** `storage.AppDataContainers`/`storage.MobileDocuments`/`iokit-user-client-class`/`mach-lookup`，否则文件与 GPU 全废（文件注释原文：`The following entitlements are required if sandbox is disabled`）。

### 6.3 内存上限（三处，别只做一处）

1. **JVM 堆**：`-Xmx` 由偏好决定；自动模式按物理内存取比例，**有 `memorystatus` entitle 用 0.4，没有用 0.25**（`JavaLauncher.m:210-217`）：
```objc
    int allocmem;
    if (getPrefBool(@"java.auto_ram")) {
        CGFloat autoRatio = getEntitlementValue(@"com.apple.private.memorystatus") ? 0.4 : 0.25;
        allocmem = roundf((NSProcessInfo.processInfo.physicalMemory >> 20) * autoRatio);
    } else {
        allocmem = getPrefInt(@"java.allocated_memory");
    }
```
2. **Jetsam 上限**：只有拿到 `com.apple.private.memorystatus` 才能调私有 API 抬高（`SurfaceViewController.m:299-310`，逐字）：
```objc
- (void)updateJetsamControl {
    if (!getEntitlementValue(@"com.apple.private.memorystatus")) {
        return;
    }
    // More 1024MB is necessary for other memory regions (native, Java GC, etc.)
    int limit = getPrefInt(@"java.allocated_memory") + 1024;
    if (memorystatus_control(MEMORYSTATUS_CMD_SET_JETSAM_TASK_LIMIT, getpid(), limit, NULL, 0) == -1) {
```
3. **连续虚拟地址空间**：分配前要能 mmap 一大块（`JavaLauncher.m:25-32` + `:218-226`）：
```objc
BOOL validateVirtualMemorySpace(size_t size) {
    size <<= 20; // convert to MB
    void *map = mmap(0, size, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if(map == MAP_FAILED || munmap(map, size) != 0) return NO;
    return YES;
}
```
失败时的错误文案直接说明了 entitlement 依赖：`Insufficient contiguous virtual memory space. Increased Memory Limit entitlement is missing, please add it via GetMoreRam app.`（`JavaLauncher.m:223`）。

→ **结论**：iOS 给 App 的可用内存上限由系统 Jetsam 决定，Amethyst 靠 `increased-memory-limit` + `memorystatus` 两个权限「人为抬高」。**具体 MB 数值随设备/iOS 版本变化，本次未查到官方数字：未确认。** 代码里唯一可引用的数量关系是「JVM 堆 = 物理内存 × 0.25（普通）/ 0.4（有 memorystatus）」，以及 Jetsam 上限 = 设定堆 + 1024MB。
