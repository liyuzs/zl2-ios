## 一、修了个真 Bug：暗色样式从来没生效

`CoreLayoutExport.swift:194` 原来是这样：

```swift
let cfg = js.commonStyle ? js.lightStyle : js.lightStyle
```

三元表达式**两边都是 `lightStyle`**。

`commonStyle == false` 的含义是「亮暗两套配色分开」，这时候本该用 `darkStyle`，但代码还是返回 light。

**后果**：系统切到深色模式后，游戏里的摇杆颜色完全不变——还是亮色那套，在黑色背景上很扎眼。

### 修法

```swift
// 摇杆
let cfg = js.commonStyle ? js.lightStyle : effectiveJoystickStyle(js)

private static func effectiveJoystickStyle(_ js: ZLJoystickStyle) -> ZLJoystickStyleConfig {
    js.commonStyle ? js.lightStyle : (isSystemDark ? js.darkStyle : js.lightStyle)
}

// 按钮样式同样处理
private static func resolveStyle(...) -> ZLStyleConfig? {
    guard let style = index[uuid] else { return nil }
    if style.commonStyle { return style.lightStyle }
    return isSystemDark ? style.darkStyle : style.lightStyle
}

// 系统外观判断
private static var isSystemDark: Bool {
    if Thread.isMainThread {
        return UITraitCollection.current.userInterfaceStyle == .dark
    }
    var isDark = false
    DispatchQueue.main.sync { ... }
    return isDark
}
```

## 二、图层切换：用「多份布局文件」绕开核心的限制

### 问题

ZL2 的控件有图层概念，按钮可以触发：

| 事件 | 含义 |
|---|---|
| `switch_layer` | 切到某层 |
| `show_layer` | 显示某层 |
| `hide_layer` | 隐藏某层 |

但核心（Pojav 的 ControlLayout）**是扁平的，根本不认识图层**。之前的导出器只能把所有可见图层的控件平铺到一个列表里。

**后果**：用户做了分层（比如「平时一层、打开背包时换一套按钮」），这个设计在 iOS 上完全失效。

### 解决思路

关键发现：核心其实**支持运行时换布局**——

```objc
// core/customcontrols/ControlLayout.h
- (void)loadControlFile:(NSString *)path;
- (void)removeAllButtons;
```

所以可以：**为每个图层各导出一份独立文件，切换时让核心重新加载。**

```
controlmap/
├── 我的布局__layer0.json      ← 默认层（平时显示的）
├── 我的布局__layer1.json      ← 第二层（打开背包时显示的）
├── 我的布局__layer2.json      ← 第三层
└── 我的布局__layers.json      ← 清单：uuid → 文件名 的映射
```

### 实现

**导出侧**（`CoreLayoutExporter`）：

```swift
static func exportAllLayers(_ layout: ZLControlLayout,
                            baseName: String? = nil) throws -> [String: String]
static func writeLayerManifest(_ layout: ZLControlLayout,
                               map: [String: String]) throws -> URL
```

对每个图层：
1. 造一个只含该层的 `ZLControlLayout`
2. 强制 `hide = false`（否则空层导不出来）
3. 导出成 `__layerN.json`
4. 把 uuid → 文件名记进映射表

**切换侧**（`ZLLayerSwitcher`）：

```swift
@objc public static func activateLayer(at index: Int) -> Bool
@objc public static func activateLayer(uuid: String) -> Bool
@objc public static func activateLayer(name: String) -> Bool
```

切换时：
1. 沿视图控制器树找 `SurfaceViewController`
2. 用 KVC 拿它的 `ctrlView`（避免 Swift 依赖 ObjC 头文件）
3. 调 `loadControlFile:` 换布局
4. 同步写 `defaultTouchCtrl`，下次启动仍在同一层

### 编辑器侧接入

保存布局时自动判断：

```swift
if zl.layers.count > 1 {
    let map = try CoreLayoutExporter.exportAllLayers(zl)
    let manifest = try CoreLayoutExporter.writeLayerManifest(zl, map: map)
    NSLog("[ZL2] 控制布局已同步 %ld 个图层", zl.layers.count)
} else {
    // 单层走原来的路径
    let name = try CoreLayoutExporter.exportAndActivate(zl)
}
```

## 三、按钮触发切换（已打通）

### 核心矛盾

| 侧 | 数据类型 |
|---|---|
| 核心按钮 | `keycodes: [Int]`（整数数组，固定长度 4） |
| ZL2 图层事件 | `{type: "switch_layer", value: "<uuid 字符串>"}` |

核心只认整数，图层事件是字符串。必须做一次映射。

### 第一版：哈希（失败的尝试）

把 uuid 做 FNV-1a 哈希，取模映射到 -1000 以下的负数区间。

实测 20 万个随机 uuid：

```
FNV + 取模 900000     碰撞 20492 次   10.246%
FNV + 掩码 2^20       碰撞 17966 次    8.983%
djb2 + 掩码 2^20      碰撞 17883 次    8.941%

理论值（生日悖论）：              约 9.54%
```

**三种方案都接近理论值——说明哈希本身没问题，是「哈希空间太小」的必然。**

但关键问题是：**图层只有 2~5 个，根本不需要 100 万个桶。**

### 第二版：顺序编号（正确方案）

```swift
static func encode(index: Int) -> Int {
    threshold - (index + 1)        // -1001, -1002, -1003 ...
}

static func decodeIndex(_ pseudo: Int) -> Int? {
    guard pseudo <= threshold else { return nil }
    let idx = threshold - pseudo - 1
    return idx >= 0 ? idx : nil
}
```

- **零碰撞**：同一布局内，序号唯一
- **反查是 O(1)**：直接算出下标，不用查表
- **实现简单**：两个表达式搞定

验证：1000 个序号往返转换，零误差。

### 完整链路

```
编辑器保存
  ↓
CoreLayoutExporter.convert()
  · 建 layerIndexByUUID 表
  · 按钮的图层事件 → encode(index) → -1001/-1002
  ↓
核心读到 keycodes = [-1001, 0, 0, 0]
  ↓
玩家点按钮 → SurfaceViewController.executebtn:
  · keycode <= -1000 → 走 default 分支
  ↓
  [ZLLayerSwitcher activateLayerByPseudoKey:-1001]
  ↓
decodeIndex(-1001) → 0
  ↓
ZLLayerSwitcher.activateLayer(at: 0)
  · 找 SurfaceViewController → KVC 拿 ctrlView
  · 调 loadControlFile: 换布局
```

### 核心侧改动

`core/SurfaceViewController.m` 的 `executebtn:` default 分支：

```objc
default:
    // 图层切换用的「伪键码」（< -1000，避开 SPECIALBTN_* 的 -1 ~ -9）
    if (keycode <= -1000) {
        if (!held) {
            Class switcher = NSClassFromString(@"ZL2iOS.ZLLayerSwitcher");
            if (switcher == nil) {
                switcher = NSClassFromString(@"ZLLayerSwitcher");
            }
            if ([switcher respondsToSelector:@selector(activateLayerByPseudoKey:)]) {
                [switcher performSelector:@selector(activateLayerByPseudoKey:)
                               withObject:@(keycode)];
            }
        }
    } else {
        NSLog(@"Warning: button %@ sent unknown special keycode: %d", ...);
    }
    break;
```

## 六、收尾：可见性三态 + 三种图层动作

### 6.1 修了一个更严重的 Bug：菜单状态下按钮全消失

核心的显示逻辑在 `SurfaceViewController.m:411`：

```objc
- (void)updateControlHiddenState:(BOOL)hide {
    BOOL hidden = hide || !(
        (isGrabbing && [button.properties[@"displayInGame"] boolValue]) ||
        (!isGrabbing && [button.properties[@"displayInMenu"] boolValue]));
    ...
}
```

`isGrabbing` 的含义是**鼠标被抓取**（进游戏了）；松开就是菜单状态。

**之前的导出器写的是：**

```swift
d["displayInGame"] = (btn.visibilityType != .inMenu)
d["displayInMenu"] = false        // ← 永远是 false
```

`displayInMenu` 恒为 false，意味着 `!isGrabbing`（菜单状态）时**所有按钮都藏起来了**。

真实后果：玩家按 Esc 打开菜单想调设置，结果所有按钮消失，只能靠手势退出。

**修法**——建立完整的三态映射：

| ZL2 `visibilityType` | `displayInGame` | `displayInMenu` |
|---|---|---|
| `always` | true | true |
| `inGame` | true | false |
| `inMenu` | false | true |

```swift
static func visibilityFlags(_ type: ZLVisibilityType) -> (inGame: Bool, inMenu: Bool) {
    switch type {
    case .always: return (true, true)
    case .inGame: return (true, false)
    case .inMenu: return (false, true)
    }
}
```

按钮、文本框、摇杆三处都改用这个函数。

### 6.2 三种图层动作的语义区分

原来 `switch_layer` / `show_layer` / `hide_layer` 都当成「切换」处理。现在区分开：

| 动作 | 伪键码区间 | 行为 |
|---|---|---|
| `switch_layer` | -2001 ~ -2999 | 切到该层（独占，其他层隐藏） |
| `show_layer` | -3001 ~ -3999 | 叠加显示（保留当前层） |
| `hide_layer` | -4001 ~ -4999 | 隐藏该层 |

编码：

```swift
static func encode(index: Int, action: Action) -> Int {
    threshold - action.rawValue * 1000 - (index + 1)
    // switch(1): -2001, -2002 ...
    // show(2):   -3001, -3002 ...
    // hide(3):   -4001, -4002 ...
}

static func decode(_ pseudo: Int) -> (action: Action, index: Int)? {
    let offset = threshold - pseudo        // action*1000 + index + 1
    let actionRaw = offset / 1000
    let index = offset % 1000 - 1
    return ...
}
```

验证：3 动作 × 100 层 = 300 组往返，全部一致。

### 6.3 叠加显示怎么实现

核心一次只能加载一份布局文件，没法「同时显示两层」。

所以导出时**预生成所有图层组合**：

```
__layer0.json           只有第 0 层
__layer1.json           只有第 1 层
__combo_0-1.json        第 0 + 第 1 层
__combo_0-2.json        第 0 + 第 2 层
__combo_0-1-2.json      全部三层
```

层数 n ≤ 6 时才预生成（子集数量 2^n - 1，6 层是 63 个文件，可接受）。

`showLayer(at:)` 时算出「当前可见层 + 目标层」的组合键，直接加载对应的 combo 文件。
