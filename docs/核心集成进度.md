## 已修复的问题（按出现顺序）

1. **CMake target 名不一致** —— `add_executable` 改成 `add_library` 后，`target_link_libraries` 还引用旧名
2. **lzma 依赖不存在** —— 只有头文件没源码，移除
3. **MACOSX_BUNDLE 属性** —— 静态库不需要，且引用了已删的 Info.plist
4. **submodule 未拉取** —— AFNetworking / fishhook / DBNumberedSlider 等目录为空
5. **MobileGlues 282MB** —— CMake 未引用，删除以控制仓库体积
6. **mach 头文件** —— `JavaLauncher.m` 缺 `<mach/mach.h>`，`task_set_exception_ports` 未声明
7. **CONFIG_BRANCH / CONFIG_COMMIT** —— CMake 变量未传，config.h 里没生成
8. **19 个 UI ViewController** —— 依赖 iOS 26 的 `UIBarButtonItem.sharesBackground`，runner 是 Xcode 16.4，全部剔除
9. **SurfaceViewController 分类文件** —— 依赖被剔除的主类，一并剔除
10. **AppDelegate.h / SceneDelegate.h** —— 被 `input_bridge_v3.m` 等引用，恢复头文件（不恢复实现）

## 下一步（按顺序）

### 1. 打包 Frameworks
把 `core/resources/Frameworks/` 复制到 App bundle 的 `Frameworks/` 目录，并在 CI 里加 rpath：
```
-altkit AltKit.framework
-libEGL libEGL.framework
-libGLESv2 libGLESv2.framework
-UnzipKit UnzipKit.framework
-CAltKit CAltKit.framework
```
外加 `libMoltenVK.dylib`、`libOSMesa.8.dylib`、`libgl4es_114.dylib`、`libfreetype.dylib`、`libglapi.0.dylib`。

### 2. 打包 JRE
从 `https://assets.angelauramc.dev/openjdk/ios-arm64/jre17-ios-aarch64.zip` 下载解压到 `java_runtimes/java-17-openjdk`。
注意 `JavaLauncher.m` 里对 JRE 路径是**写死**的，要先确认它找哪个目录名。

### 3. 接启动调用
把 `LaunchScreen.swift` 的演示动画换成 `CoreBridge.launchVersion(...)` 或 `launchJar(...)`。

### 4. 解决签名/JIT
这一步在 CI 里做不了，只能真机验证。`docs/核心集成方案.md` §6 有完整说明（StikDebug / TrollStore / get-task-allow）。

## 关键约束

- **CI 能验证的**：编译、链接、打包
- **CI 验证不了的**：运行时行为（JVM 能否启动、渲染是否正常、内存是否够）——**必须真机测试**
