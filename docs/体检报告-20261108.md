## 二、发现的真 Bug（按严重度）

### 🔴 P0-1 · MobileGlues 渲染器缺失会导致崩溃

```
代码声明：    egl_bridge.m:59  RENDERER_NAME_MOBILEGLUES = "libmobileglues.dylib"
              LauncherPreferences.m:141  列入可选渲染器
实际打包：    ❌ IPA 里没有 libmobileglues.dylib
构建系统：    ❌ CMakeLists.txt 里没有 mobileglues 构建目标
源码目录：    ❌ core/external/ 下没有 mobileglues 源码
```

**后果**：用户如果在设置里选 MobileGlues → `dlopen` 失败 → 游戏启动崩溃，且报错信息对用户完全不可理解。

**修法（二选一）**：
- A. 从可选列表移除 MobileGlues（安全，但少一个选项）
- B. 引入 MobileGlues 源码编译（完整，但工作量大）

### 🟠 P1-1 · 渲染器选项在 iOS 上是假的

设置页照搬了安卓的渲染器配置，但 iOS 只有 4 个真渲染器：

| 声明 | 实际库 | 状态 |
|---|---|---|
| GL4ES | `libgl4es_114.dylib` | ✅ 有 |
| MTL_ANGLE | `libtinygl4angle.dylib` | ✅ 有 |
| MobileGlues | `libmobileglues.dylib` | ❌ 缺 |
| VK_ZINK | `libOSMesa.8.dylib` | ✅ 有 |

**但是** UI 里的选项名、说明全是安卓话术：
- "使用 Turnip：%s" ← iOS 没有 Turnip
- "适用于 Adreno GPU" ← iOS 是 Apple GPU
- "启动器检测到您的设备为 Adreno GPU" ← 永远不触发
- "为 Zink 渲染器启用垂直同步" ← iOS 逻辑不同

**后果**：用户看懂了也选不对，选对了也不知道为什么。

### 🟠 P1-2 · 首屏文案告诉用户"这是安卓启动器"

```
ZLStrings.swift:
"欢迎使用 %1$s，这是一款专为 Android 设备打造的第三方 Minecraft: Java Edition 启动器。"
"动态 (Android 12+)"
```

**后果**：这是朋友打开 App 看到的第一句话。**信任度直接崩**。

### 🟡 P2-1 · 1536 条文案一字不差照搬

大量文案提到 Android 专属功能。需要筛出 iOS 无意义的条目并改写。
