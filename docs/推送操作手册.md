## 路线 A：生成 token 后直接推（推荐，1 分钟）

### 第一步：生成 token

打开 https://github.com/settings/personal-access-tokens

点 **Generate new token**（Fine-grained），填：

| 字段 | 填什么 |
|---|---|
| Token name | `zl2-push` |
| Expiration | `7 days` |
| Repository access | **Only select repositories** → 勾选 `liyuzs/zl2-ios` |
| Permissions → Repository permissions → **Contents** | **Read and write** |

拉到最下面点 **Generate token**，复制那串 `github_pat_...`。

### 第二步：推送（一条命令，含后续全流程）

```powershell
# 在 PowerShell 里，把刚复制的 token 填进去
.\推送并取回IPA.ps1 -Token "github_pat_xxxxx"
```

这个脚本会依次做完：

1. 推送 `master` → 线上 `main`
2. 轮询 Actions，等 `iOS Build` 跑完（超时可调）
3. 下载产物里的 `ZL2.ipa`
4. 校验体积（**小于 100 MB 说明 JRE 没打进去**，会直接报错而不是默默覆盖）
5. 替换交付包里的旧 IPA，并把新 build 号写进交付包的「项目状态-当前.md」

想手工推也行：

```bash
cd /d D:\ios-zl2
git -c http.proxy=http://127.0.0.1:7897 push "https://liyuzs:<TOKEN>@github.com/liyuzs/zl2-ios.git" master:main
```

> 注意：
> - `master:main` —— 本地分支叫 master，线上叫 main
> - `http.proxy` —— 如果这台电脑开着 Clash（127.0.0.1:7897）就带上，没开就去掉这段

### 第三步：等构建

推送成功后：
1. 打开 https://github.com/liyuzs/zl2-ios/actions
2. 应该看到一个新的 run 在跑（`iOS Build`）
3. 等 10-20 分钟
4. 成功后到 https://github.com/liyuzs/zl2-ios/releases 下载新 IPA

**验证点**：新 release 的资产应该叫 `ZL2.ipa`，**大于 100 MB**（小于 100 MB 说明 JRE 没打进去）。

```bash
# 2. 改成线上地址

# 3. 推送（需要 token）
git push origin master:main
```

## 路线 C：网页上传（不推荐）

GitHub 网页支持拖拽上传，但：

- 一次最多 100 个文件
- 单个文件最大 25 MB（我们的 `jre/*.tar.xz` 每个 20-23 MB，勉强）
- 总共要传近 800 个文件（**这条路基本走不通** —— 网页上传有 100 个/25MB 的限制）

**结论：不可行。** 除非把 `jre/` 单独处理。

如果真的只能走网页：
1. 先把 `jre/` 三个包单独上传（用 Releases 的 `jre-assets` 标签）
2. 再上传代码（去掉 `jre/` 目录）

但这样 CI 的「仓库内 jre/」那一级回退会失效，只能靠 Release 那一级。

## 推送后要确认什么

| 检查项 | 怎么查 |
|---|---|
| Actions 跑起来了 | https://github.com/liyuzs/zl2-ios/actions |
| 编译过了 | 看 run 里的 `Build for device (未签名)` 步骤 |
| JRE 装配过了 | 看 `Bundle runtime & frameworks` 步骤（这是我第 9 轮修的地方） |
| 产物生成了 | Releases 页面出现新的 `build-NNN` |
| IPA 大小对 | 大于 100 MB（完整包约 130 MB） |

**如果 `Bundle runtime & frameworks` 还是失败**，看日志里是哪一级源拿不到：
- `JRE 17: 使用仓库内资源` → 说明 `jre/` 传上去了 ✓
- `JRE 17: 尝试从 Release 下载` → `jre/` 没传上去，走了第二级
- `::warning::JRE 17 三个源都拿不到` → 三级全失败

## 常见问题

### 推送报 403 / 401

token 权限不够。检查：
- Repository access 有没有勾对仓库
- Contents 权限是不是 **Read and write**

### 推送报 timeout

网络问题。加代理参数：
```bash
git -c http.proxy=http://127.0.0.1:7897 push ...
```

### 推送报 `remote rejected` / `non-fast-forward`

线上有你本地没有的提交。先拉下来合并：
```bash
git -c http.proxy=http://127.0.0.1:7897 pull origin main --allow-unrelated-histories
```

然后解决冲突（应该没有，因为线上只有 docs 改动）。

### 推上去了但 Actions 没触发

看 `.github/workflows/build.yml` 里的 `on:` 配置，应该是 `push: branches: [main]`。
确认推的是 `main` 不是 `master`。
