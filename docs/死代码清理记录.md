## 一、发现的问题

### 问题 1：一堆写好的 UI 组件从没被使用

`ZL2App.swift` 里 `RootView` 直接进首页，但项目里有：

| 组件 | 行数 | 状态 |
|---|---|---|
| `WelcomeScreen` | 46 | 写好了，从没挂载 |
| `SplashScreen` | 69 | 写好了，从没挂载 |
| `AssetInfoSheet` | 75 | 被 `AssetInfoScreen` 取代后残留 |
| `ModsScreen` | 128 | 用假数据，被 `ModsManagerScreen` 取代 |
| `LayoutInfoSheet` | 104 | 按钮能点，但没有 sheet 监听 |

**用户视角**：第一次打开 App → 直接进首页，没有欢迎引导、没有启动闪屏；点「布局信息」→ 什么都不发生。

### 问题 2：检测方法本身有坑

第一遍用 `TypeName(` 扫，误判了 `LocalLoginSheet` / `AuthlibLoginSheet` / `MicrosoftLoginView` 为孤儿。

实际它们是这么用的（尾随闭包）：

```swift
.sheet(isPresented: $showMSLogin) {
    MicrosoftLoginView { acc in     // ← 这里没有括号紧跟
        ...
    }
}
```

**改成同时匹配 `TypeName(` 和 `TypeName {`** 才准确。

## 二、修复内容

### 1. 挂载 SplashScreen（启动闪屏）

```swift
@State private var showSplash = true

if showSplash {
    SplashScreen {
        withAnimation(.easeOut(duration: 0.35)) { showSplash = false }
    }
    .transition(.opacity)
    .zIndex(20)
}
```

启动时显示 CraftLauncher 图标 + 进度条，跑完 5 个步骤（检查环境 → 加载主题 → 初始化核心 → 扫描版本 → 就绪）后淡出。

### 2. 挂载 WelcomeScreen（首次引导）

```swift
@State private var showWelcome = !UserDefaults.standard.bool(forKey: "zl.welcomeShown")
```

只在首次启动出现，三页引导，完成后写 `zl.welcomeShown = true`，以后不再弹。

**同时把第二页做成了真自检**：

原来自检页只是写着「先做个自检」，实际什么也不做。现在真的去查：

```swift
let jre = CoreBridge.runtimeCheck()   // 检查内置 JRE
#if ZL2_CORE_LINKED
coreOK = true                          // 检查核心是否链接
#endif
```

结果实时显示：
- ✅「运行环境正常，可以开始使用了」
- ⚠️「找不到内置 Java 运行时，游戏可能无法启动」
- ⚠️「当前是模拟器环境，无法真正启动游戏」

### 3. 把 LayoutInfoSheet 接上

`ControlEditor` 有这个：

```swift
@State private var showLayoutInfo = false
chipButton("布局信息", icon: "info.circle", ...) {
    showLayoutInfo = true          // ← 设了 true
}
```

但**没有任何 `.sheet` 监听 `showLayoutInfo`**，所以点了完全没反应。

补上：

```swift
.sheet(isPresented: $showLayoutInfo) {
    LayoutInfoSheet(doc: $doc)
        .presentationDetents([.medium, .large])
        .presentationDragIndicator(.visible)
}
```

现在点「布局信息」能编辑布局名称/创作者/版本/描述，还能分享。

## 五、经验

### 双重模式检测

判断一个 SwiftUI 组件是否被使用，必须同时匹配：

```regex
TypeName\(     # 普通调用 Foo(...)
TypeName \{    # 尾随闭包 Foo { ... }
```

漏掉后者会误判 `MicrosoftLoginView { ... }`、`LocalLoginSheet { ... }` 为死代码。

### 状态变量也要查

`showLayoutInfo = true` 建了，但没人监听 —— 这类「按钮点了没反应」的 bug，
用「变量赋值点 vs .sheet/.alert/.overlay 监听点」对撞就能查出来。
