# 控制布局回写运行时

> 日期：2026-11-08
> 状态：**已实现，待真机验证**

---

## 一、问题是什么

编辑器（`ControlEditor.swift`，2502 行）做了很完整：
拖拽、属性面板、图层、样式库、导入导出 ZL2 的 JSON。

**但用户在编辑器里调好的按钮位置，进游戏后完全不生效。**

因为中间有两套完全不兼容的格式，而且没人做转换：

```
编辑器保存  →  Documents/control_layouts/<名>.json   （ZL2 格式）
核心读取    →  <AME_HOME>/controlmap/<名>            （Pojav 格式）
```

`ControlModelBridge.swift` 里有 `from(doc:)` 能转成 `ZLControlLayout`，
但没人调用；也没有任何代码把结果写到 `controlmap/`。

---

## 二、两套格式对比

| | ZL2 格式 | Pojav 核心格式 |
|---|---|---|
| 坐标 | `ZLButtonPosition(x: 0~10000, y: 0~10000)` 整数千分比 | `dynamicX / dynamicY` 浮点 0~1 |
| 尺寸 | `ZLButtonSize` 有 dp / percentage / wrap_content 三种 | `width / height` 单一 dp |
| 结构 | `layers[] → normalButtons / textBoxes / joystickButtons` 分层 | `mControlDataList[]` 扁平数组 |
| 类型区分 | 靠数组分开 | 靠 `type: "button" / "joystick"` |
| 样式 | `buttonStyle: String?` 是 uuid 引用，样式存在 `styles[]` | 直接内联到每个控件 |
| 颜色 | `ZLColorValue(argb: UInt32)` | 32 位 ARGB 整数（一致） |
| 圆角 | `ZLCorners` 四角独立 | `cornerRadius` 单值 |
| 键位 | 不直接带，在 clickEvents 里 | `keycodes: [Int]` |

## 三、实现

### 新增 `src/CoreLayoutExport.swift`

```swift
enum CoreLayoutExporter {
    static func convert(_ layout: ZLControlLayout) -> [String: Any]
    static func export(_ layout:, fileName:) throws -> String
    static func exportAndActivate(_ layout:, fileName:) throws -> String
    static func syncFromEditor(name:) throws -> String
}
```

核心换算逻辑：

```swift
// 位置：千分比 → 0~1
cx = Double(position.x) / 10000.0
cy = Double(position.y) / 10000.0

// 尺寸：dp 直接用，percentage 按 400dp 基准折算
case .percentage:
    w = Double(size.widthPercentage) / 10000.0 * 400.0

// 颜色：ZLColorValue 内部就是 ARGB，直接透传
return Int(c.argb)

// 圆角：四角取左上
cornerRadius = s.borderRadius.topStart
```

### 接了两个点

**① 编辑器保存时（`ControlEditor.saveLayout`）**

```swift
ZLLayoutStore.saveRaw(name: layoutName, data: data)      // 存 ZL2 格式
UserDefaults.standard.set(layoutName, forKey: "zl.currentControlLayout")
syncToCore()                                             // 同步核心格式
```

**② 启动游戏前（`CoreBridge.launchVersion`）**

```swift
syncControlLayoutIfNeeded()   // 读 zl.currentControlLayout → 转换 → 导出
```

### 关键：写对了核心的偏好键

`SurfaceViewController.m:464` 读的是：

```objc
NSString *controlFile = [PLProfiles resolveKeyForCurrentProfile:@"defaultTouchCtrl"];
[self.ctrlView loadControlFile:controlFile];
```

所以导出时必须同时写 `defaultTouchCtrl`，不能只写自定义键：

```swift
static var activeLayoutName: String {
    get { UserDefaults.standard.string(forKey: "control_layout") ?? "default.json" }
    set {
        UserDefaults.standard.set(newValue, forKey: "control_layout")
        UserDefaults.standard.set(newValue, forKey: "defaultTouchCtrl")  // ← 核心读这个
    }
}
```

## 五、注意事项

### 1. 键位已经接通（第 5 轮补齐）

ZL2 把按键存成字符串 `"GLFW_KEY_ESCAPE"`，核心要的是整数数组 `keycodes`。

新增 `src/GLFWKeyNames.swift` 做映射：
- 覆盖 GLFW 3.x 全部标准键码：可打印 ASCII（32..96）、功能键（256..348）、小键盘、修饰键
- 同时接受 `GLFW_KEY_ESCAPE` / `ESCAPE` / `escape` 三种写法
- 23 个用例对照 GLFW 官方 `glfw3.h` 验证通过

核心的 `keycodes` 数组固定长度 4，所以：

```swift
if codes.count > 4 { codes = Array(codes.prefix(4)) }   // 超出截断
while codes.count < 4 { codes.append(0) }               // 不足补 0
```

验证结果：

```
按钮居中 88×88 绑 Shift
  dynamicX = 0.5      ✅
  dynamicY = 0.5      ✅
  keycodes = [340,0,0,0]  ✅

多事件（W + Shift + 切换图层）
  keycodes = [87,340,0,0] ✅ 图层事件被正确忽略
```

### 2. 图层被平铺

核心没有图层概念，所以只导出 `hide == false` 的图层，
把按钮全部平铺到一个列表里。鼠标层、手柄层不导出。

### 3. 样式只取 lightStyle

`ZLButtonStyle` 有 `lightStyle` / `darkStyle` 两套。核心只有一套配色，
所以取 lightStyle。暗色模式下的控件颜色会和编辑器预览有差异。

### 4. 转换失败不阻断启动

```swift
} catch {
    NSLog("[ZL2] 控制布局同步失败（不影响启动）：%@", error.localizedDescription)
}
```

布局坏了也能进游戏（用核心自带默认布局），比启动失败好。

### 5. 图层切换事件未落地

ZL2 支持按钮触发「切换到某图层」，核心没有等价机制。
这类事件（`switch_layer` / `show_layer` / `hide_layer`）在转换时被跳过，
对应的按钮会没有动作。

## 六、真机验证要点

1. **编辑器调一个按钮位置 → 保存 → 进游戏**
   - 按钮应该在新的位置
   - 看日志：`[ZL2] 控制布局已同步：xxx.json`

2. **检查文件确实生成**

   ```
   <AME_HOME>/controlmap/xxx.json
   ```

   里面应该是 `{"mControlDataList": [...], "scaledAt": 100}`

3. **位置比例对不对**
   - 编辑器里放在屏幕正中的按钮 → 核心的 `dynamicX/dynamicY` 应该是 `0.5 / 0.5`

4. **颜色对不对**
   - 编辑器里设的红色背景 → JSON 里 `bgColor` 应该是 `0xFFFF0000`
